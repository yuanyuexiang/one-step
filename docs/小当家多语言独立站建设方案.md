本方案用于小当家及 One Step Group 现有网站重建的需求讨论、设计开发和验收。编制日期为 2026 年 11 月 12 日，软件选型遵循不购买商业插件的要求，版本为整理稿 V2，包含多语言官网、AI 智能客服、性能优化及 SEO 与 GEO。

建议建设一个统一品牌主站，采用单主域名下的语言目录，集中管理产品、案例与内容，并将服务国家作为独立业务维度。网站首期承担品牌展示、产品介绍、客户信任建立和询盘收集，支持后续增加在线交易。

# 一 建设目标与范围

网站需要让海外餐馆经营者快速理解服务内容，找到适合自己的产品，了解本地交付能力并发起咨询。同时，让运营人员能够在一个后台更新内容，让销售能够收到、分配和追踪询盘。

主要客户包括筹备开店、更新菜单、升级点餐收银和改善后厨效率的中餐馆经营者。采购决策通常需要确认适用性、费用、配送安装与售后，因此页面应围绕这些问题展开。

首期包含品牌官网、产品目录、解决方案、案例、国家服务、多语言内容管理、询盘管理、AI 智能客服、基础搜索优化、数据统计和旧站迁移。首期不包含购物车、在线付款、库存采购、物流订单系统、餐馆消费者点餐系统本体，以及完整销售 CRM。官网展示点餐系统与开发点餐系统属于不同工作范围。

网站的阶段成果是可正常访问、内容完整、询盘可追踪、后台可维护。访问量、搜索排名和成交额作为运营指标持续观察，不作为开发交付保证。

# 二 品牌与业务定位

拟定定位为“面向海外中餐馆的设计印刷、点餐系统与门店设备服务”。如果客户目前只能交付其中部分业务，应缩减对外承诺。

首页主标题示例：“为海外中餐馆提供菜单设计、点餐系统与门店设备服务”。副标题说明覆盖国家、语言支持和服务方式，具体范围经核实后填写。主要按钮为“咨询解决方案”，次要按钮为“查看产品与服务”。

小当家与 One Step Group 的关系需要明确：统一品牌名、中文名与英文名、Logo 使用、公司主体及地区联系人。页面不得混用多个未经解释的品牌名称，也不得使用未经核实的市场规模、客户数量或效果承诺。

# 四 页面内容与交互

## 首页

按“核心定位与咨询按钮、核心业务分类、按需求选择解决方案、精选案例、服务地区、交付流程、公司与售后能力、常见问题、咨询表单”组织。使用真实门店、产品和项目照片。首屏以固定主视觉为主，避免用大量轮播承载核心信息；客服入口保持收起，用户点击后展开。

## 产品与服务

暂分菜单设计与印刷、点餐与收银系统、门店展示与管理设备、后厨设备四类。旧站将广告机和监控归为智能管理系统，重做时按实际用途重新命名。分类和排序支持后台调整。

列表支持按分类筛选；有明确国家限制的产品显示可服务范围。详情包含名称、一句话价值、适用场景、图片或视频、功能与规格、可交付国家、费用说明、交付安装、售后、相关案例和咨询按钮。无统一价格时显示“获取报价”，并解释影响报价的因素。

印刷品补充尺寸、材质、印量、设计修改及生产配送流程；点餐系统补充实际功能、设备与平台兼容性、演示、安装培训和收费方式；设备补充尺寸、功率、电压、安装要求和保修。认证、兼容性和规格由客户提供并确认。

## 解决方案

以客户问题开篇，说明适用对象、业务组合、交付步骤、客户需要准备的资料、案例和咨询入口。解决方案关联已有产品，避免另外复制一套产品资料。没有交付能力的方案不发布。

## 案例

案例详情包含国家与门店类型、原始需求、交付内容、实拍、交付过程和可验证结果。没有可量化结果时只展示实际交付，不编造增长数据。客户名称、Logo、评价与照片需有使用授权。

## 国家服务页

逐国明确可售产品、配送范围、安装方式、可用语言、售后方式、工作时间和联系人。没有当地办公室时如实描述远程或合作伙伴服务；无实际服务能力的国家不发布服务承诺。

## 资源与支持

按印刷、点餐和设备组织常见问题及文章。产品资料提供语言与版本标识。站内搜索首期覆盖当前语言已发布的产品、方案、案例与文章，提供无结果提示和咨询入口。

## 联系与咨询

展示与国家匹配的邮箱、电话和经确认的沟通渠道。支持通用咨询、产品询价、系统演示和售后咨询；售后询问应进入对应队列。对外响应时效由客户确定后统一展示。

# 五 多语言与国家服务设计

## 地址规则

使用同一主域名和独立语言目录，例如 /zh-hans/、/en/、/fr/、/de/、/it/、/es/；繁体中文 /zh-hant/ 根据需求增加。示例产品地址为 /en/products/online-ordering/，示例地区页为 /zh-hans/markets/uk/。正式主域名确定为 ai-onestep.com。

语言定义页面文字；国家定义交付、联系和产品可用性。“中文加英国服务”和“法语加英国服务”都是有效组合。语言选择使用语言名称，不用国旗代替。

根地址作为默认入口，提供明确语言链接。可以依据浏览器语言给出建议，保留用户主动选择，不强制按 IP 跳转。切换语言优先进入同一内容的对应翻译；缺少翻译时提示并提供现有语言或该语言相关列表入口，不伪装成已翻译页面。

国家选择可记忆，但不覆盖语言选择。国家未知时显示通用介绍，并在询盘前要求选择国家。国家服务页中的服务范围和联系方式由网址明确决定，不随访问位置改变；缓存必须区分地区组件，防止显示其他国家联系人。

## 内容发布规则

产品基础记录共用，各语言分别维护标题、正文、搜索摘要、图片说明和资料。国家可售范围独立关联，不从语言推断。

翻译状态包括未翻译、翻译中、待审核、已发布和待更新。原文修改后标记已有译文待复核。后台能够查看缺译清单，AI 可辅助起草，由指定人员审核后发布。

导航、表单、验证错误、通知邮件、搜索提示和图片中文字均纳入翻译范围。关键营销文字采用网页文字，避免整页图片。未完成的语言不对外开放入口或进入站点地图。

建议先完成简体中文和英语，再发布经审核的法语、德语、意大利语和西班牙语。若合同要求六种语言同时上线，应将六语全部内容与校对纳入工期和验收，不把“支持语言配置”视为完成翻译。

Google 支持语言子目录，并建议通过不同 URL 和语言版本标记帮助识别页面关系。参考 [多语言与多地区网站规范](https://developers.google.com/search/docs/specialty/international/managing-multi-regional-sites)。

# 六 询盘与跟进流程

访客从产品、方案或地区页面点击咨询，表单自动关联相关内容。必填字段为称呼、服务国家、需求类别、需求描述，以及邮箱或电话至少一种；公司或餐馆名称、城市和联系偏好可选，具体必填规则在设计时确认。未选国家时不直接分给任一国家团队。

提交采用服务端校验和防刷，生成唯一询盘编号，先保存数据库，再发送通知。通知失败不丢失询盘，后台显示失败状态并可重试；重复点击通过提交标识防止重复创建。成功页显示询盘编号和经确认的处理时效，失败页保留已填信息并提供备用联系方式。

询盘记录包括语言、国家、产品或方案、来源页面、允许记录的营销来源、提交时间和跟进负责人。正文和联系方式不写入统计事件或页面 URL。

按国家及业务类型分配负责人，无匹配规则时进入公共待分配队列。首期状态为新询盘、已分配、已联系、跟进中、已转化、已关闭；支持备注、筛选和有权限的导出。成交明细和复杂销售预测由已有 CRM 或后续阶段承担。

邮件通知与自动回执作为首期能力，外部 CRM、WhatsApp API 或钉钉自动化单独确认接口与费用。首期可设置外部联系链接；点击外部联系不能直接计为有效询盘或成交。

附件上传作为可选范围。需要时明确格式、大小、访问权限与保存周期，避免公开暴露客户文件。

# 七 AI 智能客服

## 首期功能与入口

智能客服纳入首期交付，采用 AI 解答、询盘收集与人工异步跟进组合，采用 AnythingLLM 开源自托管客服，通过 Docker Compose 部署并接入模型 API。默认收起，用户点击后打开并明确标识 AI 助手；支持关闭、移动端和键盘操作，不遮挡主导航与咨询表单。首发语言与网站首发语言一致，其余语言随审核完成后开放，不承诺未经评测的语言能力。

客服继承页面语言、当前产品和用户已选国家，允许用户主动更换交流语言。涉及可售范围、配送、安装和售后时，国家未知则先询问，不按语言或 IP 猜测国家。国家切换后重新核对适用资料，避免沿用其他国家承诺。

## 知识与回答边界

知识来源为经审核发布的产品、服务地区、常见问题、交付售后与案例。回答提供相关网页链接；无匹配资料或资料冲突时说明需要业务人员确认。未发布价格、折扣、兼容性、交付日期和服务承诺不得自行补全；具体报价、合同与订单修改交由人工处理。

网站内容发布后触发知识同步，保留索引版本、更新时间、失败提示与重试；撤回资料须同步移除。同步时限在实施阶段约定并纳入验收；更新未完成时可暂停受影响问题的自动回答。知识负责人定期复核未解答问题，补充资料需走审核发布流程。

## 询盘与人工跟进

客服根据需求推荐产品与方案页面。用户请求报价、演示、人工协助或问题超出知识范围时，提供“提交给业务人员跟进”。首期明确为异步跟进，不显示无人员值守的实时在线状态；实时坐席接管列为扩展项。

提交前展示需求摘要、服务国家及联系方式供用户核对，并说明相关会话将交给业务人员。用户确认后通过与网站表单相同的询盘接口保存，关联会话编号、来源页面与语言，生成询盘编号并按国家和业务分配。通知失败仍保留记录并重试；重复提交使用请求标识去重，不自动跨会话合并客户。未提交联系方式的普通问答只记为会话，不算有效询盘。

人工负责人可查看获授权的会话原文和摘要，在统一询盘后台跟进。响应时效由客户确定并展示；售后问题按售后队列处理。用户可随时跳过聊天，直接填写表单。

## 异常处理与运营

服务超时、模型不可用、检索失败或预算达到上限时，显示可理解的提示并提供表单与当地联系方式，不伪造回答或提交成功状态。后台能够查看会话、未解答问题、知识同步情况、调用用量和预算告警，并按角色限制访问；提供会话删除和保存周期配置。

知识库内容和用户输入仅作为资料，不作为权限指令；客服不能执行付款、修改订单、导出客户信息或访问其他访客会话。上线前验证常见诱导输入不会导致越权或泄露内部资料。

## 客服专项验收

上线前由业务方审核问答评测集，覆盖每种首发语言不少于 20 个问题，包含正常产品问答、国家差异、无资料、错误前提、报价请求、转人工及故障场景。建议正常业务问题的正确且有依据回答比例不低于 90%，阈值在开发前冻结；虚构价格或承诺、跨国家误导、会话泄露及越权行为须清零并复测。

专项流程验证“英国国家加中文咨询点餐系统、申请演示、核对联系方式、确认提交、生成询盘、通知与人工后台查看”；另验证资料撤回、知识同步失败、通知失败、重复提交和预算上限。评测通过后交付知识清单、配置说明和测试记录。

| 站点设置 | 品牌、导航、页脚、默认语言、全局文案 |
| 产品分类与产品 | 规格、图片、排序、关联方案、语言版本 |
| 国家服务 | 国家、服务范围、联系人、可售产品和交付说明 |
| 解决方案与案例 | 内容、关联产品、地区、素材授权记录 |
| 文章与常见问题 | 分类、正文、语言、发布时间 |
| 询盘 | 查看、分配、状态、备注、通知失败与导出 |
| 智能客服管理 | 会话、知识库同步、未解答问题、人工跟进、调用用量与预算告警 |
| 翻译工作台 | 缺译、审核、原文变更提示 |
| 搜索与迁移设置 | 页面元数据、重定向、索引状态 |
| 用户与操作记录 | 账号、权限、发布与导出记录 |

核心数据关系为产品关联多个语言版本和多个服务国家；案例与方案关联产品和国家；询盘关联国家、来源内容和负责人。以稳定内容 ID 连接译文，不靠标题匹配。客服会话关联语言、国家、来源页面、引用资料版本及询盘编号；会话摘要与原始记录分别保存，销售可核对原文。

角色至少包括管理员、内容编辑、翻译审核和销售。内容编辑与翻译人员不默认获取客户联系方式；销售可按负责地区限制访问。敏感导出与权限操作保留记录。

内容具备草稿、预览、审核、发布、撤回和版本恢复能力。预览地址受保护，正式发布后刷新页面缓存。

# 九 视觉与使用体验

保留经确认的品牌识别，重新建立字体、颜色、按钮、卡片、表单、间距与图标规范。若沿用红黄品牌色，应限制大面积高饱和使用，提高文字与背景的区分度。

设计优先满足手机浏览和咨询，桌面端强化产品比较与内容阅读。移动端设置清晰咨询入口，避免与 Cookie 提示、客服窗相互遮挡。

页面兼容长德语词组和不同译文长度。导航、表单和弹窗支持键盘操作，有可见焦点、明确标签、图片说明与错误提示；尊重减少动画设置。图片标注真实替代文字，避免“图片名称”等占位内容。

关键设计稿包含首页、分类、产品详情、方案详情、案例详情、国家服务、文章、联系、搜索和异常状态，并检查中英文及一种长文本语言的桌面与移动布局。

# 十 技术架构与部署

采用 WordPress 单站及 Polylang 免费多语言插件、关系型数据库、询盘与邮件服务及成熟 AI 客服。部署使用现有服务器上的 Docker Compose，复用现有 Traefik 反向代理，正式主域名为 ai-onestep.com。具体容器、网络、持久化和备份要求以技术方案为准。

访问链路为浏览器经 CDN 访问网站，网站读取已发布内容；询盘经服务端保存数据库并进入通知队列；运营人员通过受保护后台维护内容。公开页面尽量缓存，询盘、聊天、预览和后台不进入公共缓存。客服服务按需加载；模型调用与密钥留在服务端，配置会话限流、超时、用量上限和服务异常降级。知识库仅索引审核通过的公开资料，不向模型开放询盘数据库或管理操作权限。

开发、验收与生产环境分离；密钥仅在服务端配置，不写入公开代码。配置 HTTPS、权限检查、输入校验、限流、日志、数据库备份、媒体备份和异常告警。后台支持多因素认证或使用具有同等能力的身份服务。

部署区域与 CDN 节点根据主要客户市场和数据处理要求确定，并在英国与欧陆代表地区实测。中国访问质量单独验证；如需中国大陆托管，相关前置要求另行核实。

数据库建议每日备份，配置保留期并在上线前做一次恢复演练。恢复目标、备份保存地点、日志保留期及维护响应时间需在运维约定中明确。

## PageSpeed Insights 性能检查

采用 Google PageSpeed Insights 作为页面性能诊断与交付检查工具，结合浏览器 Lighthouse、本地交互测试和目标市场实际访问检查使用。分别检查移动端和桌面端，关注加载速度、页面稳定性、脚本阻塞及基础无障碍和 SEO 检查；自动检查不替代多语言、业务流程及人工体验验收。工具参考 [PageSpeed Insights 官方说明](https://developers.google.com/speed/docs/insights/v5/about)。

实施分为四步：重建前保存旧站代表页面报告作为基线；新站完成后检查首页、分类、产品详情、国家服务和联系页；智能客服接入前后比较相同页面，另行测试聊天展开、提问与提交；上线后检查真实用户数据，并在首月及后续主要功能或第三方脚本变更后复测。

首发每种语言至少检查首页，主要页面模板选择代表 URL；长文本语言与图片较多页面补充检查。对同一 URL、设备模式和可比较条件各测 3 次，记录中位数、测试时间、工具版本与环境、页面版本和客服启用状态。保留完整报告、主要问题、整改措施与复测结果；无法访问或样本不足须如实记录，不能用其他页面结果替代。

重点整改首屏图片体积与加载优先级、图片尺寸预留、字体加载、缓存、无用脚本与第三方客服资源。客服按需加载并预留布局空间。PageSpeed 常规加载测试不能完整代表聊天后的交互，需另测客服实际操作，不用实验室脚本阻塞指标替代真实用户 INP。

验收结合已约定的性能指标和主要问题整改结果，不要求单次 100 分，也不把工具评分等同于搜索排名或询盘转化。第三方脚本与测试环境可能导致波动，需说明原因并保留可比较复测结果；影响关键操作或造成明显性能退化的问题须在上线前解决。真实用户数据达到样本要求后，再按其统计周期和页面或站点范围观察；没有数据不代表通过或失败。

# 十一 搜索优化与内容获取

每个已发布语言页面设置独立标题、描述、可读 URL、语言声明和可抓取正文。内容相同的页面模板不代表正文可以只翻译导航。

对应译文之间配置双向 hreflang，包含自身，按需要提供 x-default。正常独立译文使用自身规范地址，不统一指向英文；只将已发布、可索引且内容对应的页面加入语言关系。站点地图与内部链接使用最终正式地址。参考 [语言版本标记规范](https://developers.google.com/search/docs/specialty/international/localized-versions)。

根据页面实际内容设置组织、面包屑等结构化数据，不添加虚构评价或不真实商品信息；不承诺搜索增强展示。筛选、预览、测试和重复参数页设置明确索引策略。

国家专属内容使用独立国家服务页承载。单纯用 Cookie 替换联系人无法代替可被搜索发现的地区页面。

内容围绕餐馆经营者的采购与使用问题展开，执行以下市场规划、页面优化及上线后运营安排。

## SEO 市场与页面规划

SEO 从建站阶段启动，上线后持续运营，以目标国家的有效询盘为业务目标。优先选择一个主要国家和两至三项可稳定交付的核心业务，依据利润、交付能力、现有客户与需求证据确定；英国菜单印刷、点餐系统与收银设备仅作为讨论示例，不视为已确定市场。

建站前整理品牌词、产品服务词、国家需求词、采购选型问题与售后问题，结合旧站搜索数据及可用关键词工具核实当地表达和需求。每条记录包含国家、语言、搜索意图、证据来源及日期、目标页面、优先级和咨询动作；未取得搜索量或竞争数据时标记未知，不编造数值。

交付关键词与页面对应表：明确由哪个页面承接哪类需求。相近意图优先合并，避免多个页面重复竞争；只有服务范围和内容确有差异时才增加地区页。先完善产品、解决方案、国家服务与案例，再以文章解答采购问题，并链接到对应服务和咨询入口。

## 本地化内容与可信度

各语言分别检查当地搜索表达、产品适用性、收费方式、配送安装和售后，不机械复制一套关键词。服务页说明交付内容与边界，案例使用授权素材和可核实结果；文章标注负责人及必要的更新时间。

AI 可以辅助研究整理、起草和翻译，产品事实与承诺由业务人员确认，译文由指定审核人批准。客服高频问题经去除个人信息后可归纳为选题，不能直接发布聊天记录。不得为操纵排名批量生成仅替换国家或城市名称、缺少独立价值的页面。参考 [Google SEO 入门指南](https://developers.google.com/search/docs/fundamentals/seo-starter-guide) 与 [AI 内容说明](https://developers.google.com/search/docs/fundamentals/using-gen-ai-content)。

品牌资料统一公司名、域名与有效联系方式。可争取真实客户、合作伙伴和相关行业资源中的自然介绍与链接；不购买批量垃圾链接，不虚构当地办公室。如需本地商家资料运营，须核实实际经营地点和平台资格后另行确定范围。

每月新增或更新页面数量、语言、字数或内容深度、案例数量、校对责任、修改轮次、工具费用和审批周期在运营范围表中约定，不以未确定的产量报价。客户负责提供真实产品与案例资料并确认业务事实；执行方负责研究、结构优化、约定内容制作与发布；各语审核人负责本地化校对，销售负责线索反馈。

# 十二 GEO 与 AI 搜索可见性

GEO 纳入网站建设与持续运营，目标是让联网 AI 搜索能够发现公开页面、准确理解品牌和服务范围，并有机会引用官网内容。抓取成功、品牌被提及、官网被引用和获得推荐分别记录，不视为同一结果；不承诺所有模型收录、固定推荐位置或进入模型训练。站内 AI 客服服务于访客咨询，不等同于外部 AI 搜索优化。

SEO 与 GEO 共用网站技术、业务资料和内容，避免重复建设和收费。Google 表示其 AI 搜索功能沿用 SEO 基础，无额外特殊优化要求。参考 [Google AI 搜索说明](https://developers.google.com/search/docs/appearance/ai-features)。

## AI 抓取与公开资料

检查 robots.txt、页面索引与摘要控制、CDN、防火墙及访问日志，排查对目标搜索服务的误拦截。核心产品、国家服务、安装售后和常见问题使用可访问的网页文字与稳定链接，不仅存在于图片、登录页面或聊天窗口。保留后台、客户资料和私有会话的访问保护，不为抓取开放内部数据。

上线前按目标平台官方规则建立抓取配置清单，记录用途、公开路径、验证方法和规则更新时间。ChatGPT 搜索检查 OAI-SearchBot 访问；搜索与训练权限分开决定，允许搜索发现不自动意味着同意训练。其他服务逐一按当时官方文档核实，不仅凭 User-Agent 字符串判断身份，也不为抓取关闭整体安全防护。参考 [OpenAI 抓取规则](https://developers.openai.com/api/docs/bots)。

llms.txt 可在有明确用途时作为实验性补充，不作为上线必需项或 AI 引用保证，也不能替代正常网页、索引配置及站点地图。结构化数据描述页面真实可见事实，不额外虚构所谓 AI 推荐标签。

## 品牌事实与可引用内容

建立品牌事实表，统一小当家与 One Step Group 的关系、公司主体、品牌名称、官网、国家服务、产品规格、费用规则和联系方式。各语言页面与对外资料使用一致事实，业务负责人确认后发布，标注必要的更新时间与适用条件。

重点内容包括产品与服务说明、费用构成、选型比较、国家安装配送、售后规则和真实案例。页面先回答具体问题，再解释适用人群、条件、步骤与证据，使用明确标题、参数表和相关页面链接。比较内容注明依据与局限，不编造竞争对手情况或客户效果。

每个事实有负责人及依据；变更时同步更新相关译文、公开问答与站内客服知识库。客服高频问题经匿名归纳和审核后可转为公开文章，客户聊天与联系方式不作为公开资料。与客户或合作伙伴的真实介绍可增加品牌信息来源，不使用虚假评价或批量灌水制造声量。

## AI 搜索测试与月度监测

首轮建议围绕优先国家及两至三项主营业务建立 20 至 30 个真实问题，包含品牌核实、无品牌的服务查找、采购比较、费用、安装售后和国家差异，保存问题原文及语言版本，避免全部使用含品牌名的诱导提问。

选择在目标市场可用的 ChatGPT 搜索、Google AI 搜索、Copilot、Perplexity 等作为候选平台，首轮实际覆盖的平台及数量在范围表中冻结。每题在独立会话中测试并保留完整样本，记录日期、地区、语言、平台、可识别的模型或模式、是否启用联网、提问原文、答案、引用 URL 和事实错误。关键问题可重复抽样以观察波动，不通过选择性保留结果制造成功率；无法使用的服务标记未测。

每月报告区分品牌提及比例、官网引用比例、业务事实准确情况、被引用页面及可识别的 AI 来源访问和有效询盘。所有比例附本轮问题与样本数，仅代表测试集，不代表全市场份额。访问来源缺失时记为未知；抓取日志不能证明内容被引用，引用也不能直接计为询盘。

在客户账号有权限且功能可用时使用 Bing Webmaster Tools AI Performance 辅助分析其支持场景的引用；数据范围按平台说明记录，不外推为所有 AI 服务。参考 [Bing AI Performance](https://www.bing.com/webmasters/help/ai-performance-9f8e7d6c)。Google 等平台若不提供独立 AI 明细，报告保持汇总口径，不虚构平台级精确归因。

## GEO 执行与验收边界

建站交付包含抓取配置与检查记录、品牌事实表、约定重点页面的内容整理、初始测试问题集及可用平台基线报告。未正式公开的页面无法完整验证外部抓取或引用时，先完成技术检查，并在公开上线后补充基线；未出现引用如实记录，不等于开发失败。

上线后与 SEO 九十天计划衔接：第一个月确认可访问性和基线，第二个月补充关键问题及证据，第三个月依据引用、事实错误和有效询盘复盘。持续工作纳入 SEO 与 GEO 月度运营，约定平台数、问题数、语言、抽样次数、内容产量与工具费用。

验收依据资料准确、公开页面可访问、配置与检查完成、测试可复查以及报告按约交付。模型是否引用或推荐属于外部结果，不设为建站通过条件。发现 AI 错误描述时先核对官网及外部资料，修正自有内容并复测，必要时通过平台反馈，不承诺立即改变模型答案。

# 十三 数据统计与运营

首期统计客服打开、提问、未解答、人工跟进请求、客服转询盘、接口错误与调用费用，以及页面浏览、产品查看、咨询按钮、表单开始、提交成功、提交错误、电话与外部联系点击、语言和国家选择。事件不携带姓名、邮箱、电话、需求正文或聊天原文。客服效果按已保存的有效询盘衡量，不把聊天次数或模型自报的解决率当作成交。

核心指标为有效询盘数、有效询盘率、首次联系时长及询盘转化；同时按国家、语言、页面和渠道分析。有效询盘口径需明确，排除测试、垃圾和重复数据。外部联系点击单独统计，不直接当作线索。

上线后前 30 天以建立基线、排查流程问题为主，检查 PageSpeed Insights 与可用的真实用户数据，之后按月优化高访问低咨询的页面，并在主要页面、客服或第三方脚本变更后复测性能。转化率分母、统计周期和同意状态应保持一致。

隐私告知需准确反映实际采集字段、服务商、使用目的、保存时间和联系渠道。若部署非必要统计或营销追踪，按适用要求配置同意机制；营销订阅与业务咨询分开。最终政策由客户或其指定顾问审核。客服平台采用 AnythingLLM 自托管，管理面不直接公开，前台通过站点受控接口访问；平台数据和知识索引纳入独立备份。自托管不等于模型本地运行，首期仍可能向模型 API 发送必要问题与检索内容。智能客服另需明确会话保存周期、模型与客服供应商接收的数据、访问与删除流程，并在聊天入口说明 AI 身份和数据用途；仅传递回答所必需的信息，联系方式不作为知识库内容。

# 十四 旧站迁移与上线

首先取得六个旧子域名的页面清单、可用后台导出、媒体素材、访问与搜索数据，以及 DNS、服务器和域名管理权限。逐页判断保留、合并、重写或下线，核实旧图片使用权和联系方式。

建立迁移表，字段包括旧 URL、页面类型、语言、内容状态、新 URL、处理方式、负责人和检查结果。以实际语言映射新目录，不能直接把 cn 全部视为简体中文；旧中文站目前展示大量繁体内容，需逐页判断。

对应内容使用服务器端永久重定向，优先直接抵达最终页面，避免链式跳转。没有等价内容时按情况返回 404 或 410，不能把所有旧页面强行跳到首页。

上线前备份旧站，测试新站和映射，在暂存环境检查索引限制；上线时部署新站、启用映射、检查证书、解除正式页面的索引限制并提交站点地图。保留旧域名和子域名控制权，安排持续维护重定向，参考 Google 至少保留一年的迁移建议。参考 [网站迁移规范](https://developers.google.com/search/docs/crawling-indexing/site-move-with-url-changes)。

上线后持续监控 404、重定向、询盘保存、邮件失败和收录。出现关键故障时按预案回滚应用与配置；回滚需保留上线后新收到的询盘，不能直接用旧数据库覆盖。搜索表现可能在迁移期间波动，应持续观察。

功能方向已确定，最终开发范围须通过下表量化。未确定数量标记待盘点，不默认为无限量交付；中英先发为建议，六语首发与繁体支持由客户确认。

| 范围项 | 首期规则 | 冻结依据 |

| 页面模板 | 首页、列表、产品、方案、案例、国家服务、资源、关于、联系、搜索与异常状态 | 原型确认后逐项编号，明确模板复用 |
| 内容数量 | 产品、方案、案例、文章、FAQ、下载资料分别计数 | 旧站盘点及内容台账，标记原文与译文数量 |
| 国家与语言 | 建立国家乘语言发布矩阵，只开放有交付及审核能力的组合 | 国家负责人、翻译负责人及上线批次 |

内容台账逐项记录内容 ID、类型、国家、原文语言、源文件、素材权利、译文状态、审核人、目标 URL 与完成日期。缺失内容必须明确为补写、暂缓发布或剔除，不能用占位文案通过验收。

首期产品展示以询价为主，不实现实时汇率或自动报价。如展示参考价格，记录原始币种、税费是否包含、适用国家、有效期及审核人；没有可确认规则则显示询价。国际电话支持国家区号，地址、日期和通知时间按用户或负责人所在地表达。

用户所在国家无此产品时，页面提示不可用范围并给出替代产品或咨询入口，不展示无法履行的购买承诺。表单所选国家与页面不一致时提示核对，以用户最终确认的服务国家分配询盘。

# 十六 技术选型与交付依赖

开发前输出技术决策表，确定前端与 CMS、搜索实现、数据库、部署区域、媒体服务、邮件与 AI 供应商。每项说明选择理由、限制、授权或订阅费用、备份导出及更换供应商办法。现有方案描述架构方向，尚未冻结具体产品，不能直接作为已完成的技术选型。

邮件配置独立发信域名或子域名，验证 SPF、DKIM 及 DMARC 配置与实际送达。覆盖通知、回执、退信和重试；只提供电话时不发送邮件回执，仍展示页面确认。第三方回调校验来源并防重复处理，连续失败进入告警和人工处理清单。

图片和视频建立媒体规范：响应式尺寸、压缩、替代文字、封面和必要字幕；首屏外资源延迟加载。下载文件记录语言、版本、可见范围及失效替换规则。公开搜索不得返回草稿、后台或客户上传内容。

测试站通过访问控制隔离并限制索引，开发与生产使用不同密钥及测试数据。上线使用真实内容完成一次从访问、聊天或表单、保存、通知到销售查看的完整预演。

# 十八 项目确认与上线门槛

需求冻结前确认品牌、首发国家与语言、页面与内容数量、接口和预算；设计冻结前确认原型、组件、主要文案与移动端布局；上线前确认内容及译文、政策、联系方式、数据规则和运维责任。

验收参数另附签字表，明确测试 URL、设备及网络、并发或流量预估、性能阈值、客服知识同步时限、通知重试及告警时间、RPO 与 RTO、支持的浏览器版本。所有参数在开发前确定；当前建议值不自动升级为合同承诺。

客户指定业务验收人及各语审核人，执行方提供测试证据和遗留清单。关键问题关闭后由指定负责人确认上线窗口；DNS 与证书检查同时覆盖新站及旧站重定向。上线后安排观察期，具体天数、负责人和响应窗口在上线单中确定。

# 二十 验收标准

| 项目 | 验收要求 |
|---|---|
| 页面与内容 | 范围表内页面完整，无占位内容；品牌、规格和联系方式经确认 |
| 多语言 | 约定上线语言完整；切换保持内容对应；缺译提示正确，无无声混用 |
| 国家服务 | 同一语言可切换国家；范围、联系人和表单路由与配置一致 |
| 产品后台 | 可创建、修改、审核、发布和撤回产品与译文，无需修改代码 |
| 询盘 | 成功写入、编号、负责人、来源与语言正确；模拟通知失败仍保留记录 |
| 智能客服 | 完成语言、国家、资料引用、缺失信息、询盘确认、人工跟进及故障降级评测；不得虚构报价、交付或售后承诺 |
| 客服知识更新 | 修改、撤回资料后按约定时限更新索引；旧承诺不再作为有效依据 |
| 客服费用与隔离 | 用量可查看，预算告警和上限生效；无法读取其他会话或后台客户数据 |
| 校验与防刷 | 必填、邮箱电话、异常提交与重复点击处理正常 |
| 权限 | 未授权账号无法查看或导出询盘；预览与管理接口受保护 |
| 搜索与链接 | 当前语言搜索正常；无结果与 404 可继续导航；电话邮箱可用 |
| SEO 与迁移 | 元数据、语言关系、规范地址和站点地图正确；迁移表逐条检查通过；交付初始关键词与页面对应表，验证 Search Console 配置及询盘来源记录 |
| GEO | 品牌事实与公开资料经审核；交付 AI 抓取检查、初始问题集及可复查基线，平台未测和引用缺失如实记录；不以模型推荐作为开发验收条件 |
| 设备与浏览器 | 在约定的桌面 Chrome、Edge、Safari 及 iOS Safari、Android Chrome 验证关键流程 |
| 性能 | 按 PageSpeed Insights 检查计划覆盖代表页面与首发语言，移动及桌面各测 3 次并记录中位数；交付整改与复测报告，验证客服接入前后变化及聊天交互 |
| 运维 | HTTPS、生效备份、恢复演练、告警和部署回滚记录齐全 |

建议性能目标为 LCP 不高于 2.5 秒、CLS 不高于 0.1；上线前以明确测试环境的实验室结果验收，上线后再观察真实访问数据。真实访问交互性能不应在没有样本时宣称达标。指标作为项目建议，最终测试环境和阈值在开发前确认。

上线门槛为阻断与严重缺陷清零；其他遗留问题须有书面记录、负责人及处理时间。以“英国服务国家加中文页面提交产品咨询”为完整样例，验证页面、表单、保存、分配、通知和后台跟进全链路。

# 二十一 预算构成与范围控制

费用按设计、模板与前端、后台与权限、多语言、询盘与通知、内容整理、翻译校对、智能客服服务接入与知识整理、问答评测、旧站迁移、建站基础 SEO 与 GEO 配置和基线测试及测试培训分别估算。上线后 SEO 与 GEO 运营按月或按阶段单独报价，共用技术与内容工作避免重复计费，明确研究、页面与文章产量、案例、语言校对、AI 测试平台与问题及抽样次数、月报及工具费用；持续运营不自动计入建站或故障维护范围。持续费用单列域名、托管、存储与流量、邮件、付费服务和维护，以及客服订阅、模型调用、知识检索与存储费用。客服由客户持有服务账号，设置月度预算、告警阈值和用量上限；到达上限时保留表单和人工跟进入口。

报价前冻结独立页面模板数、首发语言、每类产品与案例数量、旧 URL 数、每页文字量、图片加工量、第三方接口数和修改轮次。一个产品发布六语通常生成六个内容页面，但不是六套设计模板；翻译和录入仍需计量。

新增商城付款、库存、会员、在线设计编辑、自动报价、复杂 CRM 或第三方系统集成，均作为变更项单独估算。智能客服首期包括基础 AI 问答、产品引导、询盘收集和人工异步跟进；实时人工坐席、语音客服、WhatsApp 消息自动化和自动报价作为扩展项。新增语言还需计入系统文案、产品内容、通知模板及校对，不能只按增加一个语言按钮计算。

变更流程为记录需求、评估费用与工期、确认后实施；未完成确认的新增范围不挤占既定验收标准。
