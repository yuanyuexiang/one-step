# 小当家独立站成熟平台选型调研

调研日期：2026 年 11 月 12 日。依据现有建设方案和各产品官方资料进行桌面调研，未购买账号、安装插件、实测性能或取得供应商报价。能力区分为文档确认、需要集成以及待验证；推荐属于本项目工程判断。

## 一 结论与原方案纠正

首期是多语言产品展示与询盘网站，尚无确定的在线支付、库存或复杂订单需求。多语言、SEO、GEO 和 AI 客服本身都不是必须使用 Next.js 的理由。

将 WordPress 单站加多语言插件、轻量主题和必要业务扩展列为第一验证路线；Webflow 为偏重可视化维护和托管服务的备选。Next.js 加 Payload 保留为深度业务定制备选，不再默认首选。若在线交易成为近期核心目标，再优先评估 Shopify 或 SHOPLINE；若客户明确需要统一 CRM、销售与 ERP，则评估 Odoo。

原技术方案把发布快照、独立翻译工作流、任务系统、销售管理和知识同步都放入定制开发，增加了维护责任。应先判断哪些必须由官网承担：询盘和人工跟进可以交给成熟 CRM，AI 可以使用成熟服务；只对验证不能满足的部分定制。

## 二 评估标准

硬条件为同一主域名的独立语言 URL、中文与英国服务可组合、页面可抓取、询盘持久化及通知失败不丢失、客户账号与资料可导出、旧子域名可重定向、能接入客服。安全保护和数据权限不能通过前端隐藏代替。

比较成本必须包含设计与内容，而非只比较月费；比较控制权必须包含编辑器、数据库与业务功能，而非只看是否能导出 HTML。性能和 SEO 应以实际模板、图片、插件及脚本测试，不能以语言或框架名称推断排名。

## 三 候选平台对比

| 路线 | 本项目适配判断 | 原生或生态能力 | 需要验证与补足 |
|---|---|---|---|
| WordPress 自托管或托管版 | 第一验证路线 | 内容、媒体、角色；多语言、表单、SEO 由成熟插件提供 | 国家产品模型、行级销售权限、通知重试、知识撤回与兼容性 |
| Webflow 加 Localize | 第二路线 | 可视化设计、CMS、多语言目录与本地化 SEO | 六语套餐、国家业务模型、外部 CRM、细粒度权限与退出迁移 |
| Shopify | 交易优先时推荐复评 | 商品、交易、Markets、多语言与国际 SEO | 询价型业务需应用或定制；国家 URL 与既定语言目录设计差异 |
| SHOPLINE | 交易或批发优先时复评 | 商城、多语言、B2B 生态 | 套餐、询价应用、国家语言组合、导出及接口权限 |
| Wix | 简化营销站可选 | 可视化、多语言与语言 SEO 设置 | 复杂内容关系、地区权限、导出新旧产品适用范围 |
| Odoo Website 与 CRM | 经营系统整合时可选 | 官方网站模块包含翻译及 SEO 等配置 | 具体版本、CRM 衔接、授权、定制托管和多语言发布实测 |
| 国内外贸 SaaS，如领动 | 有中文交付支持需求时入围演示 | 官网宣传多语种、模板与询盘获客能力 | 必须核验真实 URL、人工校对、六语价格、导出、机器人访问及客服 API |
| Ghost | 不列主选 | 内容出版与主题翻译 | 官方多语言内容建议独立安装或翻译服务，匹配本项目结构需额外工作 |
| Next.js 加 Payload | 深度定制备选 | 渲染框架、可编程 CMS、权限与版本底座 | 表单后台、语言审批、任务可靠性、运维和业务界面均需实现验证 |

## 四 WordPress 推荐组合与边界

采用一个 WordPress 站点，不按国家或语言拆六个安装，也不先做 Headless。以区块主题和结构化字段实现设计，尽量避免重复页面构建器及重叠 SEO、缓存和翻译插件。

建立 product、solution、case、market 等内容类型；country 独立分类或关系字段，不将语言当国家。产品规格等共享字段与译文字段分开。语言目录由 WPML 或 Polylang 提供，两者先选一种验证，生产不并装。

WPML 官方提供目录语言格式及翻译管理产品；Polylang 同样支持目录语言。需要试验原文变更、草稿发布、字段共享及国家关系是否符合本项目，不能将插件支持翻译等同于独立审核全部满足。

表单选具有数据库记录、通知、导出及接口能力的成熟方案。Gravity Forms 官方提供按条件发 webhook，可接外部 CRM；webhook 存在不等于已经具备幂等和可靠重试。询盘先落地，通知单独处理；后台若需要严格国家隔离，可交给已有 CRM，或编写小型专用扩展并测试列表、详情、REST、导出和附件权限。

WordPress 原生角色是能力模型，不自动提供按国家的每条询盘访问控制。不能因使用插件就跳过权限验证。使用真正后台调度器执行必要任务，不单纯依赖有人访问页面时触发任务。

客服用供应商嵌入组件加必要服务端连接层，发布和撤回通过事件同步；服务商不能可靠撤回时保留禁用与降级手段。密钥不出现在网页代码。发布、搜索、重定向和统计优先使用成熟工具，业务扩展集中维护，避免散落主题中。

官方依据：[WPML URL](https://wpml.org/documentation/getting-started-guide/language-setup/language-url-options/)、[Polylang URL](https://polylang.pro/documentation/support/guides/url-modifications/)、[WordPress 权限](https://wordpress.org/documentation/article/roles-and-capabilities/)、[Gravity Forms webhook](https://www.gravityforms.com/feature/webhooks/)。

## 五 SaaS 的实际约束

Webflow 支持本地化 CMS、语言子目录及 SEO 标记，能力不是简单翻译按钮。截至调研日官方套餐表显示 Essential 最多三个附加 locale、Advanced 最多十个；六种总语言意味着五个附加 locale，不能直接按最低本地化档报价。还需确认 CMS 条目、团队权限、语言费用及维护账号。

Webflow 可导出前端代码，但官方说明导出不包含 CMS 数据功能和本地化页面内容，不能把前端导出理解为整站可无损自托管。内容数据应另行验证导出或 API。参考 [套餐](https://webflow.com/pricing)、[本地化 API](https://developers.webflow.com/data/docs/working-with-localization/)、[代码导出限制](https://help.webflow.com/hc/en-us/articles/33961386739347-How-do-I-export-my-Webflow-site-code)。

Shopify 可以单主域名多语言，不必多域名。其官方规则说明主市场可以语言目录，次级市场目录组合语言与地区；因此并非不能做中文加英国，而是需要在真实 Markets 配置下核对路由。若只做一个主市场加通用国家服务页，也需验证可售范围与市场模型是否一致。官方已处理部分国际 SEO，不能以自建 SEO 为理由排除。参考 [国际地址](https://help.shopify.com/en/manual/international/managing-international-domains)、[国际 SEO](https://help.shopify.com/en/manual/markets/seo)。

SHOPLINE 官方套餐展示商城、多语言及 B2B 能力，询价也有应用路线；具体插件和地区版本不可混同，须演示本项目流程。参考 [套餐](https://www.shopline.com/pricing)、[B2B 应用](https://apps.shopline.com/detail?appHandle=b2b_wholesale_solution)。

Wix 不宜笼统说完全不能导出。新开发文档存在代码导出与外部托管 beta，而传统产品另有不同限制；必须确认客户采用的编辑器、beta 可用性以及动态功能迁移范围。参考 [导出 beta](https://dev.wix.com/docs/studio-two/code-your-site/export-your-site/host-an-exported-site-outside-wix)、[多语言 SEO](https://support.wix.com/en/article/wix-multilingual-optimizing-seo-settings-for-multilingual-sites)。

国内 SaaS 的 AI、SEO 和 GEO 营销描述不等于抓取、引用或询盘效果保证。要求演示站与导出样本，询问到期后域名、网页、译文、媒体、询盘和重定向如何移交；未公开的权限和价格标记未知，不武断判定不支持。[领动官网](https://www.leadong.com/)。

## 六 三年成本比较方法

三年总成本 = 首次设计实施及迁移 + 三年订阅与托管 + 插件许可与翻译额度 + AI、邮件与存储用量 + 维护与升级人工 + 内容校对与运营 + 退出迁移成本。内容生产与 AI 用量应按同一范围比较，不能在某方案中漏算。

| 路线 | 首期开发判断 | 持续费用与责任 | 主要成本风险 |
|---|---|---|---|
| WordPress | 标准页面通常少于全定制；业务扩展另计 | 主机、许可、插件兼容、备份与安全维护 | 插件堆叠和后期业务扩展 |
| Webflow/Wix | 标准营销页面可复用可视化能力 | 平台、语言、席位、外部 CRM 与客服 | 套餐升级、限制和迁出重建 |
| Shopify/SHOPLINE | 交易能力复用高，询价改造额外 | 商城、应用、团队与交易相关费用 | 为非交易场景付费和应用组合 |
| Odoo | 若已有 Odoo 可复用，否则实施范围易扩大 | 授权、托管、实施与升级 | 官网项目演变为 ERP 项目 |
| 定制栈 | 通常投入最高，需实现业务基础 | 云资源、研发、测试与升级责任 | 人员依赖与低估维护人工 |

以上是工程判断，不是供应商报价。WPML 官方当前 CMS 标价 €99，含一年支持更新，不能当整个站点年成本；续费、税费和自动翻译额度另核。其他平台按地区、结算周期与套餐动态报价，暂不输出未经核实的三年金额。[WPML 定价](https://app.wpml.org/purchase)、[Shopify 定价](https://www.shopify.com/pricing)、[Webflow 定价](https://webflow.com/pricing)。

正式估算分别给中英首发和六语首发两张预算表，统一内容数、人员权限、客服调用、访问量、维护时效和三年周期。不能仅以开源无许可费判定零成本，也不能只以 SaaS 月费判定更贵。

## 七 什么情况才选 Next.js 加 Payload

满足以下条件时才优先：需要复杂结构化业务和精细工作流、统一平台内严格管理多国销售权限、多来源数据和多个前端、成熟插件实测无法满足，且客户接受长期开发维护预算。选择前记录具体不满足项、绕行方案及成本，而非因开发者熟悉 TypeScript。

Payload 也是成熟 CMS，原方案不是所有模块从零开发，但它提供的是可编程底座；Next.js 不会自动提供面向运营人员的完整多语言网站软件。不能宣传定制天然性能更好或天然更利于 SEO/GEO。

## 八 原型验证与最终决策

优先制作 WordPress 验证站，使用同一组中文英文内容、一个英国地区页、一个产品、一个案例、一个询盘及客服流程；扩展一个长文本语言验证布局。Webflow 若进入决选，使用同一数据做可比演示。此调研不代表原型已经执行。

| 验证 | 通过条件 |
|---|---|
| 路由与发布 | 同主域名目录、当前页切语、缺译提示、独立审核与更新提示可操作 |
| 国家独立 | 中文加英国、切换国家、未知或不可售国家行为正确且缓存不串 |
| 询盘 | 保存先于通知，失败可恢复，并发重复提交有明确策略 |
| 权限 | 销售不能通过页面、API、导出或附件读取其他国家线索 |
| 客服 | 回答有来源，内容撤回后不沿用，人工确认后创建一次询盘 |
| 迁移 | 六个 host 的路径规则、文件、404/410 和证书可实施 |
| 性能 | 同一内容和脚本条件下测试 PSI 及实际交互，不用空模板比分 |
| 移交 | 客户能登录、更新内容，导出产品、译文、媒体与询盘并做恢复演练 |

先估算标准平台加扩展的实际成本，再与原定制路线比较。若 WordPress 通过硬条件且维护责任清晰，则作为正式首选并重写实现章节；否则按失败项选择 Webflow、外部 CRM 混合架构或定制路线。客户必须选择业务体验和总成本，不必固守最初设想的每一项内部实现。

## 九 本次研究边界

核查官方文档涉及 WordPress/WPML/Polylang、Webflow、Shopify、SHOPLINE、Wix，并对 Odoo、Ghost 和国内 SaaS 作筛选。Odoo 深层文档抓取超时，相关判断仅按官网索引及模块说明，不据此断言完整权限或流程能力；Ghost 的多语言建议见其 [官方说明](https://ghost.org/docs/faq/translation/)。尚未取得真实内容规模、预算、维护人员及未来交易时间表，因此不作不可撤回的平台决定。
